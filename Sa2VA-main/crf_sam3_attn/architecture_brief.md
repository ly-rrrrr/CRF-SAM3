# 指代视频分割候选重排系统架构设计书

- 文档版本: 精简架构版 v2
- 目标: 只描述当前方案本体、关键改进与方法论，不包含具体运行指令。

---

## 1. 问题定义与设计目标

### 1.1 问题定义
给定视频序列与自然语言指代表达式，系统首先召回一组候选对象 tube，再在候选集合内完成重排，输出与表达式最匹配的目标掩码序列。

### 1.2 核心挑战
1. 背景捷径: 通用 VLM 可能根据整帧场景语义给错误候选高分。
2. 候选同质化: 多个候选 often 属于同一类别，仅靠独立二分类难以分开。
3. 上游误差传递: 类别抽取或召回偏差会直接影响后续判别。
4. 多数据集训练分布差异: 单一训练目标容易牺牲某一数据集上的细粒度判别能力。

### 1.3 设计目标
1. 训练-推理打分口径一致。
2. 候选间相对排序能力强。
3. 明确建立“候选即锚点主语”的判别语义。
4. 抑制背景与场景捷径。
5. 训练流程可稳定扩展到联合训练。

---

## 2. 总体架构

系统采用三阶段流水线：

1. 语义引导候选召回阶段
2. 候选重排微调阶段
3. 推理评估阶段

三个阶段之间通过“候选元信息 + 掩码序列 + IoU监督”解耦：

1. 上游只负责召回候选
2. 下游只负责在候选集合内做排序
3. 训练可基于离线缓存稳定进行

---

## 3. 阶段一: 语义引导候选召回

### 3.1 概念抽取
系统先从表达式中抽取：

1. `category`: 主召回词
2. `backup_categories`: 可选回退词
3. `num_targets`: 目标数量先验

当前原则是：
1. `category` 优先保持表达式中的主体名词
2. `backup_categories` 作为安全回退机制，而不是任意属性短语集合
3. 抽取得到的语义结果直接影响候选召回质量，因此其定义必须稳定

### 3.2 候选召回
用主召回词驱动视频实例召回器在全视频传播，得到每帧候选掩码及对象 ID，并聚合成对象 tube。

### 3.3 候选监督构建
将候选 tube 与 GT 时序掩码对齐，计算对象级 IoU，作为后续 listwise 排序训练的监督基础。

---

## 4. 阶段二: 候选重排微调

### 4.1 输入表示
每个候选由若干采样帧表示。每帧将候选 mask 叠加到原图，形成“候选已被显式标出”的多模态输入。

### 4.2 锚点式判别语义
当前 prompt 不再只是“候选是否匹配表达式”，而是更明确地要求模型执行：

1. 将被 mask / highlight 的对象视为表达式的锚点主语
2. 判断当表达式 grounded 在该对象上时，整句是否成立

这一定义的目的不是改写网络结构，而是减少“场景 somewhere 满足表达式”这一错误捷径。

### 4.3 打分定义
系统区分两种分数：

1. 推理主分数:
   - `s_i = P(Yes | expression, candidate_i)`
2. 排序辅助分数:
   - `r_i = logit(Yes) - logit(No)`

其中：
1. 推理与最终排序输出使用 `P(Yes)`
2. 难负样本排序约束使用 `r_i`，因为 logit gap 更稳定

### 4.4 Listwise 排序学习
训练单元是“同一表达式下的全部候选”，而不是逐候选独立分类。

给定候选集 `C`、正样本集 `P`、温度系数 `tau`：

`L_cls = logsumexp(s_j / tau, j in C) - logsumexp(s_j / tau, j in P)`

该目标直接学习组内相对排序，而非独立 pointwise 判别。

### 4.5 Mask-aware 软对齐约束
为了抑制背景捷径，在中间视觉-文本表征上加入软约束：

1. 提取文本 token 与视觉 token 表征
2. 计算视觉 token 对文本的相关性分布
3. 将候选 mask 下采样到 token 网格
4. 最大化语义质量在候选掩码区域内的占比

该约束的特点是：

1. 不做硬裁剪
2. 保留上下文
3. 只惩罚“主要语义质量落在候选外”的情况

### 4.6 当前难负样本约束
新增的难负样本损失不再使用 `top-k` hardest negative，而是直接惩罚所有仍威胁正样本胜出的负样本。

设正样本参考分数为 `pos_ref`，安全间隔为 `margin`，则所有满足：

`neg > pos_ref - margin`

的负样本都视为违规负样本，并统一施加惩罚。

该设计的含义是：

1. 不是只打最高分负样本
2. 而是要求正样本整体上稳定胜出
3. `margin` 控制正样本与负样本之间的安全距离

### 4.7 总体优化目标

`L_total = L_cls + lambda_align * L_align + lambda_rank * L_rank`

其中：
1. `L_cls`: listwise 主排序损失
2. `L_align`: mask-aware 软对齐损失
3. `L_rank`: 违规负样本惩罚项

### 4.8 参数高效微调策略
当前仍采用参数高效微调：

1. 视觉编码器冻结
2. 主要更新语言侧 / 融合侧投影层上的 LoRA

这意味着模型主要学习“如何读取视觉 token 并围绕锚点作出判断”，而不是重训整套视觉 backbone。

## 5. 联合训练策略

### 5.1 为什么改为联合训练
串行微调会导致不同数据集之间的优化轨迹断裂。当前改为联合训练，使多个数据集在同一优化过程中共同约束模型。

### 5.2 数据集特定监督
当前联合训练不是简单拼接数据，而是为不同数据集设置不同监督参数，例如：

1. `MeViS`:
   - 更宽松的 `pos_iou`
   - `threshold` 式负样本策略
2. `DAVIS / Ref-YTROS`:
   - 更严格的 `pos_iou`
   - 更强调单目标细粒度区分

### 5.3 软平衡采样
联合训练采用 `repeats` 做软平衡：

1. 先扩大各数据集有效长度
2. 再在拼接后的总数据集上统一采样

这样既保留简单训练管线，又避免大数据集完全主导优化。

## 6. 阶段三: 推理与评估

### 6.1 候选打分
对每个候选对象计算 `P(Yes)`。

### 6.2 候选排序
按照分数降序排序，选取最优候选或前 `K` 个候选作为最终输出。

### 6.3 输出形式
输出为目标对象在全视频上的掩码序列，可直接用于 `J / F / J&F` 评估。

## 7. 关键设计决策与理论动机

### 7.1 为什么从 pointwise 转向 listwise
任务本质是“同组候选谁最匹配”，而不是“单候选是否匹配”。因此 listwise 更贴近最终目标。

### 7.2 为什么采用锚点式 Yes/No
因为任务真正要判断的是：

1. 这个被标出的候选是否可作为表达式主语
2. 表达式在该候选上是否成立

而不是整张图是否 somewhere 满足表达式。

### 7.3 为什么保留上下文而不用硬裁剪
很多表达式的证据不只在候选本体内，还在其邻域关系、穿戴物、交互物或位置语义中。硬裁剪会直接破坏这些线索。

### 7.4 为什么难负样本损失改成“全违规负样本”
当前目标不是只击败某一个 hardest negative，而是让正样本稳定胜出，因此直接惩罚所有仍压制或逼近正样本的负样本更符合目标。

### 7.5 为什么仍冻结视觉编码器
当前任务仍属于候选级重排，而不是开放世界检测。冻结视觉 backbone 可以降低成本并保持稳定；主要学习集中在“如何根据文本围绕锚点读取已有视觉表征”。

---

## 8. 已验证的当前方法边界

### 8.1 优势
1. 与候选重排目标一致
2. 对背景与整场景捷径更敏感并可显式抑制
3. 可扩展到联合训练
4. 训练与推理口径更统一

### 8.2 局限
1. 最终性能仍受候选召回质量上限限制
2. 冻结视觉端意味着局部细节表征提升有限
3. 联合训练可能稀释某单数据集上的专项能力
4. 锚点式 prompt 与损失约束能减少捷径，但不能完全替代更强的结构化对齐能力

---

## 9. 后续优化方向

1. 继续分析联合训练与单数据集专项能力之间的权衡
2. 更系统地评估锚点式 prompt 对不同数据集的影响
3. 在不显著增大成本的前提下增强局部视觉-文本对齐
4. 进一步统一训练、验证、导出与评测协议
