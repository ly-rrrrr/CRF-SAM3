软件名称：面向泛电力场景的多视角协同异常感知与人员搜索软件

概述：

本软件面向泛电力场景中的异常行为识别、终端隐患排查和跨区域目标检索等应用需求设计，针对复杂场景下普遍存在的目标尺寸微小、背景遮挡严重、视角变化明显以及语义表达不充分等问题，构建覆盖多视角感知、异常状态判定和人员搜索的综合测试对象。与单一视觉检测或单一模态识别方式相比，该类软件更强调在复杂环境中对细粒度目标、跨镜目标以及具有语义指向性的异常目标进行稳定发现、准确判定和持续检索的能力。

从能力构成上看，本软件涉及三类互相关联的核心功能。第一类为多视角时空协同感知能力，重点验证软件在多摄像头或多视角输入条件下，对小目标、遮挡目标以及跨视角重复出现目标的检测、关联和连续感知能力。第二类为文本语义引导的异常检测与状态判定能力，重点验证软件是否能够结合图像信息与文本语义描述，对具有特定含义的异常目标或状态变化区域进行定位、识别和结果输出。第三类为面向实际场景的人员搜索与跨镜检索能力，重点验证软件在给定查询目标后，是否能够从候选图像或视频帧中完成目标检测、特征匹配、排序检索和结果记录。

本测试需求文档覆盖创新点3所涉及的整体能力范围，应用场景包括电表侧异常行为排查、终端设备隐患识别、站所重点目标搜索以及跨区域监控场景下的人员检索等。代表性旁证材料包括《COSOS-1k: A Benchmark Dataset and Occlusion-aware Uncertainty Learning for Multi-view Video Object Detection》《Cross-view Semantic Alignment for Livestreaming Product Recognition》《Bottom-Up Foreground-Aware Feature Fusion for Practical Person Search》和《Dataset and Approach for Helmet-Wearing Detection With Edge Devices at Construction Sites》等论文。其中，人员搜索部分的测试流程与指标口径可由当前已获取的 deep-person-search 项目实现直接支撑，其余部分按照创新点3原始描述和代表性论文主题进行合理测试需求设计。

测试目的：

本测试旨在评估创新点3相关软件是否具备面向复杂电力场景的综合智能感知能力，重点验证其在多视角条件下对微小目标和遮挡目标的发现与关联能力、在文本语义约束下对异常目标和状态变化的定位与判定能力，以及在给定查询目标条件下完成人员搜索、跨镜检索和结果输出的能力。同时，测试应在统一测试口径下对人员搜索部分形成可复核的客观评测流程，并对创新点3其余能力模块给出合理、可执行的测试需求设计，为后续开展现场测试或第三方测试提供依据。

测试内容：（1）软件功能性测试——适合性

首先，应测试软件在多视角输入条件下的目标发现和连续感知能力。测试应覆盖多摄像头同步视频或多视角图像场景，并包含目标尺度较小、部分遮挡、跨视角重复出现和背景干扰较强等情况。软件应能够对目标进行检测，并在有需要的场景下输出跨视角关联、时序跟踪或多视角融合后的结果信息。若软件能够在上述场景中稳定完成目标发现与结果输出，则判定该项测试满足要求，否则判定不满足要求。

其次，应测试软件在文本语义引导下的异常目标识别与状态判定能力。测试输入应包括待检测图像或图像对，以及与目标异常类型、目标属性或状态变化有关的文本语义描述。软件应能够依据图像信息与文本描述的对应关系，对异常目标、可疑区域或状态变化位置进行定位、分类或判定，并输出可读的检测结果。若软件能够根据语义描述稳定完成目标定位和状态判定，则判定该项测试满足要求，否则判定不满足要求。

再次，应测试软件的人员搜索与跨镜检索能力。测试应采用查询目标与候选图像分离的输入方式，要求软件根据给定查询人员，在候选图像或候选视频帧中完成目标检测、特征匹配、相似度排序与结果返回。软件应能够输出包含候选图像、候选区域和排序结果的检索信息，并支持对命中结果进行人工复核。若软件能够稳定完成检索任务并输出结构化结果，则判定该项测试满足要求，否则判定不满足要求。

此外，应测试软件结果记录与过程复核能力。对于人员搜索部分，当前工程实际具备将排序结果写入 results.json，并保存 gallery_features.pkl、gallery_boxes.pkl 和 probe_features.pkl 等中间结果文件的能力；对于创新点3的其余能力模块，测试应要求系统输出可复核的检测结果、状态判定结果或日志信息，以支撑后续人工核查和结果追溯。若软件能够保留关键测试过程输出并支撑复核，则判定该项测试满足要求，否则判定不满足要求。

测试内容：（2）软件功能性测试——正确性

对于多视角时空协同与特征聚合增强能力，测试对象应为多视角输入条件下的目标检测、跨视角关联与遮挡场景感知结果。测试数据应覆盖同步多视角场景、小目标场景、遮挡场景以及不同视角互补场景，测试输出应包括目标位置、目标类别以及必要的视角关联结果。评价时应统计精确率（Precision）、召回率（Recall）、平均精度均值（mAP）等检测类指标，并在遮挡较轻与遮挡较重、单视角与多视角等场景下进行对比，以验证多视角信息互补对目标发现与稳定感知的支撑作用。若软件能够在统一数据和统一评价口径下输出稳定、可核验的检测结果，且各项指标达到预设测试要求，则判定该项满足要求，否则判定不满足要求。

对于文本语义引导的异常检测与状态判定能力，测试对象应为图像与文本语义共同驱动下的异常目标定位、异常类别识别或状态变化判定结果。测试输入应包含待分析图像、历史对比图像或前后采样图像，以及对应的异常描述、对象描述或状态说明文本。测试输出应包括异常区域位置、异常类型、状态变化结论以及必要的结果说明。评价时应统计准确率、精确率（Precision）、召回率（Recall）、F1 值或状态判定准确率等指标，并在背景复杂、目标微小、语义描述明确与描述模糊等场景下检验软件的稳定性。若软件能够依据文本语义对异常目标进行有效定位和判定，并形成可复核输出，则判定该项满足要求，否则判定不满足要求。

对于人员搜索与跨镜检索能力，测试对象应为查询目标与候选图像之间的检测和检索结果。当前工程可直接支撑该部分评测，数据基准可采用 PRW 和 CUHK-SYSU，其中工程参数中的数据集名称分别对应 prw 与 ssm。当前评测流程实际包括候选图像遍历、检测框及候选特征提取、查询框特征提取、检测性能评估和搜索性能评估等步骤。检测侧应统计召回率（Recall）和平均精度（AP），并可区分全部检测结果与仅对有标注身份目标的检测结果；搜索侧应统计召回率（Recall）、平均精度均值（mAP）以及前1、前5、前10命中指标（top-1、top-5、top-10）。必要时，可在统一测试设置下将 baseline、OIM 和 NAE 等工程中已出现的方法作为对比对象。若软件能够在 PRW 和 CUHK-SYSU 协议下完成统一口径的检测和检索评估，并输出可复核的排序结果文件，则判定该项满足要求，否则判定不满足要求。

测试方案：

测试应遵循统一数据来源、统一评价口径、统一结果记录方式的原则进行设计。多视角检测部分应选取具有多摄像头同步观测关系或多视角对应关系的测试样本，重点覆盖微小目标、遮挡目标、背景复杂和跨视角互补等场景；文本语义引导异常检测部分应选取包含异常行为、状态变化或潜在隐患的样本，同时为每组样本提供与待检对象或异常类型相关的文本描述；人员搜索部分应按查询目标与候选图像分离的形式组织测试数据，并保留完整的真值标注信息，以便开展检测与检索两类评测。整个测试过程应尽量保持不同能力模块之间的测试条件可比、输入输出关系明确、评价口径统一。

在多视角时空协同与特征聚合增强能力的测试中，应先对多视角输入进行统一预处理，并保证不同视角之间在时间或语义上的对应关系。随后，应在相同测试集上分别开展目标检测与跨视角关联评估，记录不同场景下的目标检出情况、召回情况以及关联稳定性，并在需要时对单视角结果与多视角融合结果进行对比，以验证多视角协同机制对小目标发现和遮挡恢复的作用。对于存在遮挡或目标尺寸过小的测试样本，还应单独统计相关场景下的检测结果，以体现复杂条件下的感知能力。

在文本语义引导的异常检测与状态判定测试中，应首先整理测试图像、前后对比图像和对应文本描述，并对异常类别、状态变化类型或关注目标进行标注。随后，应将图像信息与文本语义一并输入待测软件，记录软件给出的异常区域、异常类型或状态判定结果。测试时应覆盖典型语义表达、相近语义表达和背景干扰较强的样本，以观察软件在语义约束下对特定异常目标的识别稳定性，并通过统一统计口径汇总准确率类和召回率类指标。对于前后状态变化判定场景，还应关注判定结论与真实状态之间的一致性，以避免仅对局部外观差异做出误判。

在人员搜索与跨镜检索测试中，当前工程实际采用先提取候选图像中检测框与目标特征、再提取查询目标特征、之后分别开展检测评估和搜索评估的流程。对候选图像的处理过程中，工程会保存候选框和特征；对查询目标的处理过程中，工程会提取查询框特征；在评估阶段，工程会分别计算检测侧的召回率和平均精度，以及搜索侧的召回率、平均精度均值和前1、前5、前10命中指标。对于 CUHK-SYSU，当前工程还支持按照图库规模协议进行评测；对于 PRW，当前工程按去除查询图像后的候选集合进行搜索评估。评测完成后，排序结果可写入 results.json，中间特征和检测结果可写入相应缓存文件，以支撑结果复核。

所有测试过程都应保存必要的测试配置、输入样本标识、输出结果和指标统计信息。对于已有代码支撑的人员搜索部分，应保留代码生成的结果文件和中间缓存文件；对于其余两类能力，应要求测试过程输出检测结果、状态判定结果或统计汇总结果，以便后续开展人工抽查、结果回溯和第三方复核。若后续补充真实测试数据、架构图或现场记录，可在此方案基础上进一步完善具体测试样本说明、附件名称和结果记录表述。

测试原理：

本测试的基本原理是在统一测试集、统一输入条件和统一统计口径下，对创新点3相关软件的多视角感知能力、异常判定能力和人员搜索能力进行客观评估。对于多视角检测与跨视角协同部分，测试重点在于考察软件能否利用不同视角之间的互补信息提升目标发现能力，并通过精确率、召回率和平均精度均值等指标评价其对微小目标、遮挡目标和复杂背景目标的检测效果。对于文本语义引导异常检测部分，测试重点在于考察软件能否在图像信息和文本语义共同作用下，准确识别具有明确语义指向的异常目标或状态变化，并通过准确率、精确率、召回率、F1 值或状态判定准确率等指标反映其判定正确性与稳定性。

对于人员搜索与跨镜检索部分，当前工程的评测原理可以直接作为测试依据。其基本思路是先在候选图像中完成目标检测并提取候选特征，再对查询目标提取查询特征，随后基于候选特征与查询特征之间的相似度进行排序检索，并结合真实标注计算检测指标和检索指标。当前工程中，检测评测使用设定的检测阈值过滤候选框，其中 baseline 和 OIM 默认检测阈值为 0.5，NAE 默认检测阈值为 0.01；搜索评测中使用 score_thresh=0.5 和 base_iou_thresh=0.5 作为基础评测口径，并根据候选目标与真实目标的匹配情况统计召回率、平均精度均值和 top-k 指标。对 CUHK-SYSU 数据集，当前工程支持按照不同图库规模协议进行评测；对 PRW 数据集，当前工程按照排除查询图像后的候选图像集合进行评测。通过上述流程，可以较为客观地评价软件在候选目标检测、查询目标匹配和排序检索等环节的综合性能。
