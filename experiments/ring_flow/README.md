# ring_flow：固定圆心环流（第三版设计的最小实现）

设计文档：「固定圆心环流：视频理解与生成的微积分范式（第三版）」。

这是一个独立的实验包，和 CRF-SAM3 仓库无关，也不依赖任何预训练模型。只需要 `torch`、`numpy` 和 `Pillow`。

## 三句话

1. 每一帧都用**同一个固定的环形滤波器**过滤：圆心固定在画面中心，第 k 圈半径为 r₀·qᵏ，越往外采样越模糊。模糊本身就是热扩散，所以**半径就是扩散时间**。
2. **理解 = 导数**：只用相邻两帧在环上的变化率，不训练，就能解出镜头的推拉、旋转和平移，并找出画面里独立运动的东西。跨时间的答案（总共推近多少、转了多少度、跳了几次）由问题按需积分。
3. **生成 = 积分**：微积分引擎是两条轴上的流匹配。径向流从圆心一圈一圈往外生成；时间流只看「当前值 + 当前变化率」，学习加速度的分布，不带任何记忆。

## 文件

| 文件 | 作用 |
| --- | --- |
| `rf/ring.py` | 固定环形滤波器 `RingFilter`（编码、渲染）和泼溅补细节 `fit_splats` / `render_splats`。纯数学，没有可学参数 |
| `rf/motion.py` | 理解 = 导数场：`estimate_motion` 用 4 个未知数的稳健最小二乘解镜头运动，残差就是局部运动；`integrate` 做按需积分 |
| `rf/world.py` | 连续时间的合成二维世界：带纹理的背景，在重力下弹跳的物体，以及推拉、旋转、平移的镜头。可以按任意帧率渲染，镜头运动的真值是解析的 |
| `rf/model.py` | 微积分引擎：`RadialFlow`（径向，从内往外）和 `TemporalFlow`（时间，状态只有值和变化率） |
| `rf/data.py` | 渲染合成视频，编码成环形系数，并缓存 |
| `rf/train.py` | 训练两条流并评估：不同帧率下的推演误差，以及外圈补全 |
| `rf/check_motion.py` | 免训练检验，合成视频有真值。也可以用 `--frames_dir` 跑你自己的视频帧 |
| `rf/demo_render.py` | 表示检验：环形加泼溅，对比同样数据量的均匀网格 |
| `tests/test_all.py` | 8 个单元测试，CPU 上约 5 秒 |
| `scripts/run_all.sh` | 统一入口 |

## 怎么跑（在 `ring_flow/` 目录下）

```bash
pip install torch numpy pillow pytest   # 服务器上通常已经有了
python -m pytest -q tests               # 8 passed

bash scripts/run_all.sh check    # 免训练检验，约 1–2 分钟（CPU）
bash scripts/run_all.sh render   # 表示检验，约 1 分钟（CPU）
GPU=0 bash scripts/run_all.sh train   # 引擎训练：先渲染 3000 段合成视频（CPU 多进程），再在 GPU 上训练
FRAMES_DIR=/path/to/frames bash scripts/run_all.sh real   # 对真实视频帧做免训练读出
```

`train` 的可调环境变量：`N_TRAIN`（默认 3000 段）、`STEPS`（默认 20000）、`WORKERS`（渲染进程数，默认 8）。数据缓存在 `data/` 下，第二次运行直接读缓存。

## 输出看什么

- `runs/check_motion/synthetic.json`：每种镜头运动（静止、推拉、旋转、平移、混合）的估计误差 `mae_*`，与真值平均幅度 `mean_abs_gt_*` 对比；`local_motion_hit_rate` 是局部运动峰值落在运动物体上的比例；`zoom_factor_abs_err` 和 `rotation_deg_abs_err` 是按需积分后，总推近倍数和总旋转角的误差。
- `runs/demo_render/metrics.json` 和 `compare.png`：四行依次是原图、只用环、环加泼溅、同样数据量的均匀网格。分别给出全图和中心圆盘内的 PSNR。
- `runs/ringflow_v0/metrics.json`：
  - `temporal`：在训练帧率（1/15 秒）和没见过的帧率（1/30、1/60 秒）下，推演 1 秒的误差，以及它和两个基线（不动、匀速外推）的比值。**帧率不变性 = 三个帧率下的比值接近**。
  - `radial`：给定内一半的圈，生成外一半，看外圈 PSNR 是否高于「填平均值」基线。
  - `rollout_dt*.png`：第一行真值，第二行推演结果；`radial_completion.png`：真值、补全、基线；`radial_samples.png`：从圆心开始无条件生成。

## 已知的局限（v0）

- 时间流直接在复数系数上做加法积分。但旋转在系数上是**相位旋转**（乘法），推拉是**沿圈平移**，加法形式对这两种运动并不自然。下一版应该把镜头运动作为群作用分离出来，引擎只学剩下的部分。
- 径向流目前生成的是每圈的系数本身，还没有生成泼溅细节点。
- 可积性损失（先径向后时间 = 先时间后径向）还没加。
- 扫视（把圆心挪到别处）还没实现，圆心始终在画面中心。

## v1：环之后全部是神经网络（2026-11-24）

v0 里能跑通的部分都是固定数学，唯一学习的部分没有赢过简单基线。v1 只保留**固定圆心 + 由内向外的环**作为「视网膜」（采样方式），之后的一切都由网络从无标注视频里自己学：

| 部分 | 是否学习 | 作用 |
| --- | --- | --- |
| 视网膜 `RingFilter.samples` | 固定 | 每帧 → 24 圈 × 64 点 × 3 色 |
| 编码器 E | 学习 | 一帧的环采样 → 状态 h，每个极坐标格子（第 k 圈、第 p 个扇区）一个 token，共 24×8=192 个 |
| 导数网络 G（= 理解） | 学习 | (h_t, h_t − h_{t−1}) → 很小的运动码：每格 4 个数 m + 全帧 8 个数 g。这是过去传给未来的唯一信息，没有更多记忆 |
| 积分器 V（= 生成） | 学习 | (h_t, m, g) → dh/dt，再走一步 h_{t+1} = h_t + dt·dh/dt。换帧率只换 dt |
| 解码器 D | 学习 | h → 环采样，所有预测都和视网膜真实看到的比 |

训练目标（全部自监督，不用任何标签）：重建当前帧 + 预测后两帧。训练时帧间隔随机取 1/30 或 1/15 秒。

评估（`runs/v1/metrics.json`）：
1. `recon_psnr`：状态 h 能不能装下一帧。
2. `rollout`：只给两帧，自己往后推 0.4 秒，和「复制最后一帧」「按当前变化率外推」比。`dt=1/60` 是训练时没见过的帧率。`model_vs_copy_mse` < 1 表示赢了复制。
3. `probes`（只在合成数据上，真值**只在这里**用）：从运动码线性读出镜头推拉/旋转/平移的 R²（1 = 完全读出，0 = 读不出）；运动大的格子是否就是有物体的格子（AUC，0.5 = 瞎猜）。同样的检查也在一个**没训练过**的同结构网络上跑一遍，作为对照。

```bash
GPU=0 bash scripts/run_all.sh v1                          # 合成视频，3000 段，30000 步
GPU=0 FRAMES_DIR=/path/to/frames bash scripts/run_all.sh v1real   # 你自己的视频帧（子文件夹 = 不同视频）
```
可调：`N_TRAIN`、`STEPS`、`WORKERS`；模型大小用 `python -m rf.v1_train --help` 看。

## v2：环上的运动方程（2026-11-24）

把视频看成环网格上的一条方程：`du/dt = −v_k·∂u/∂k − v_n·∂u/∂n + q`。固定圆心让推拉变成沿圈号平移、旋转变成沿角度平移，所以画面内容这个“难项”被约掉，只需要知道“挪了多少”。网络 G 从当前帧和变化率读出流场 (v_k, v_n) 和源项 q；生成 = 把方程往前积分任意时长（半拉格朗日，对均匀流动任意步长都精确）。只用 15 帧/秒训练，测试 1/60～2/15 秒输入。

| 版本 | 开关 | 做法 | CPU 结果（600 段，3000 步；误差/复制，0.267 秒） |
| --- | --- | --- | --- |
| v2 | 默认 | 流场 + 自由源项 | 0.67 / 0.66 / 0.66 / 0.62；镜头读数差，源项偷懒 |
| v2.1 | `--global_cam --lam_loc` | 学 4 个镜头数 + 局部流 | 失败：局部流塌成 0，源项变大 |
| v2.2 | `+ --lam_res` | 再要求方程在当下成立 | 仍失败：只有旋转 R² 0.43 |
| **v2.3** | `--cam_lsq --lam_res` | 4 个镜头数直接从方程解出（稳健最小二乘），网络只学局部流和源项 | **0.61 / 0.58 / 0.59 / 0.58**；源项降为 1/30；旋转 R² 0.68，横移 0.85 / 0.43；推拉仍读不出 |

```bash
GPU=0 bash scripts/run_all.sh v2      # v2
GPU=0 bash scripts/run_all.sh v21     # v2.1（失败的版本，留作对照）
CUDA_VISIBLE_DEVICES=0 python -m rf.v2_train --out runs/v23 --cache data --cam_lsq --lam_res 1 --lam_loc 0.01 --lam_q 0.02 --n_frames 7 --n_train 3000 --steps 20000
```
