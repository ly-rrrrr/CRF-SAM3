# P1-A 设计说明：Ground 响应图怎样给 SAM3 用

日期：2026-11-19　|　依据：你 11-12 的 4 例热力图 npz、仓库源码（`category_grounding_mvp`、`crf_sam3_demo.py`、`SAM3-DMS/sam3/model/*`）、SAM3 官方示例 notebook、`crf_sam3_attn/cache_reports` 里的训练缓存失败清单

---

## 1. 结论

1. **热力图不该被当成"目标框"，而应当作"区域门控"。** 它能可靠回答"类别证据在哪里"，但分不清是哪一个实例。实例分离交给 SAM3 自己完成。
2. **SAM3 的提示方式：先文本，再按需补，候选取并集。** 不要把文本和框塞进同一次提示。原因是 SAM3 源码里"文本 + 框"是一次重置后的语义查询，框只在那一帧充当 exemplar，含义是"长得像这个的东西"，不是"这一个实例"。
3. **最对口的补法是"门控下的低阈值检测找回"（rescue）。** SAM3 只把分数 ≥0.7 的检测变成新轨迹（`new_det_thresh=0.7`），分数在 0.2–0.7 之间但真实存在的实例永远进不了候选。热力图负责指出哪块区域有证据但没有任何候选，SAM3 在那一帧放低阈值，只取落在这块区域里的检测，再用 tracker 把它传播成 tube。

## 2. 你的热力图实际能提供什么（4 例，12 帧）

| 聚合方式 | GT 所在连通块覆盖的 GT 比例 | 找到 GT 区域的帧（覆盖≥0.5） | 该块中 GT 的纯度 | 实例级帧（纯度≥0.8） | 质量最大的块就是 GT |
|---|---|---|---|---|---|
| **MAX（推理时实际用的）** | **0.95** | **12/12** | 0.62 | 3/12 | 11/12 |
| 单 slot Q5（事后最佳） | 0.71 | 9/12 | 0.71 | 7/12 | 8/12 |
| 8 个 slot 平均 | 0.27 | 3/12 | 0.55 | 6/12 | 3/12 |

由 `p1a.heatmap_diag --diagnostic-dir` 在你的 npz 上算出，逐帧明细见 `runs/diag_4cases/`。

**解读：**
- **MAX 图的召回是安全的。** 每一帧里 GT 几乎都完整落在某个高响应块里。
- **但它是类别级的。** "the leading car" 那一例中，三辆车并成一个块（纯度 0.44–0.58）；"the object speaking" 一例里人和两个柜子一起亮。这和你的观察一致。
- **slot 已经塌缩。** Q4–Q7 两两相关系数在 0.8 以上（gorilla 一例 0.90–0.98，car 一例 0.82–0.95），Q0/Q1/Q3 几乎不响应。所以没法把"每个 slot 当一个实例假设"来拆分。挑单个 slot 也不稳：Q5 在 3 例里最好，在 pickup 一例里几乎失效。
- **分辨率很粗。** ReVOS 每帧只有 11×20 到 22×40 个 token，用块的外接框去当 SAM3 的框，必然框进相邻的同类物体。

所以热力图能可靠回答的只有一件事："这一片区域有该类别的证据。"这恰好就是判断"召回有没有漏"所需要的信息。

**样本说明：** 这 4 例来自 Ground 内部验证集，帧是"目标可见帧"采样的，偏乐观。`heatmap_diag` 可以在几百条失败样本上重算同一张表，第一步就应该跑它。

## 3. SAM3 三种提示的真实语义（读源码确认）

| 调用 | 实际行为 | 源码位置 |
|---|---|---|
| `add_prompt(text)` | 先 `reset_state`；文本作用于所有帧，传播时每帧都跑检测器 | `sam3_video_inference.py` 的 `add_prompt`（842 行起） |
| `add_prompt(text, boxes)`，在第 t 帧 | 同样先重置；框只存进 `per_frame_geometric_prompt[t]`，**只在第 t 帧和文本一起**当 exemplar，其他帧只用文本；第一个框按"visual prompt"处理，且只允许 1 个 | 同上 882–904 行，`_get_visual_prompt` 178 行，`_run_single_frame_inference` 357 行 |
| `add_prompt(boxes)`，不带文本 | `allow_new_detections = has_text or has_geometric_prompt(当前帧)`，**只有第 t 帧能产生新目标**，之后全靠 tracker | 同上 366–393 行 |
| `add_prompt(points, labels, obj_id)` | tracker 实例提示（SAM2 式），不经过检测器；label 1/0 表示正/负点击，2/3 表示框的两个角点 | 同上 1477 行起、`sam/prompt_encoder.py` 107 行 |
| 新轨迹门槛 | `score_threshold_detection=0.5`，`new_det_thresh=0.7` | `model_builder.py` 727–730 行 |

官方示例也是这个用法：视频 notebook 演示"文本召回 → 用点击增加或修正某个对象"，图像 notebook 才演示 exemplar 框。SAM3 论文的原话是："exemplar prompts are particularly useful when the model initially misses some instances"。也就是说，**exemplar 和点击都是在文本结果之后用来纠错的**，不是和文本并列的另一种输入。

### 为什么不同时给文本和框

- 会重置会话、重跑检测，主候选集也会跟着变，论文主结果就不再可比。
- 热力图框是类别级的粗框，当 exemplar 会把检测往"一团同类"上带。
- 框只作用于那一帧，对其他帧没有帮助。

### 为什么不在文本没召回时直接用热力图框

可以做，但只对"0 候选"这种情况有意义（DAVIS 失败样本里没有 0 候选，ReVOS 验证集空候选占 0.96% / 3.15%）。而且框的质量取决于热力图，所以包里把它放成对照组（`exemplar` 模式）。

## 4. 方案：证据门控的召回补全

```
文本召回（不改，recall24/keep7）→ 候选 C
        │
Ground MAX 图，在 M 个 Ground 帧上找连通块（阈值 = max(0.5, 0.6·帧内最大值)）
        │
覆盖率 = 块内响应质量落在 C 的掩码上的比例
覆盖率 < 0.5 → "未覆盖证据"，按质量取前 B=2 个        ← 不需要 GT，可部署
        │
rescue：在该帧以阈值 0.2 跑 SAM3 检测（只此一帧）
        → 取 token 面积 ≥50% 落在该块内、且与 C 的 mask IoU <0.5 的检测
        → 用检测框 + 内点作为 tracker 实例提示，双向传播 → 新 tube
point（对照）：在块内局部峰值放正点击 → tracker → 新 tube
exemplar（对照）：文本 + 块外接框作为 exemplar
        │
新 tube 与 C 的时空 IoU >0.7 视为重复，丢弃；每个模式最多新增 3 条
最终候选 = C ∪ 新 tube，交给 Verify
```

**要点：**
- **热力图只负责门控和选区域，实例边界来自 SAM3 自己的检测。** 这样类别级热力图的缺点不会传到 mask 上：三辆车并成一块没关系，SAM3 检测器会给出三个独立实例，没被召回的那几个就是要补的。
- **取并集，所以 oracle J\* 只增不减。** 代价是多给 Verify 几个候选。误触发率需要在成功样本上测（README 第 4 节）。
- **完全免训练，Ground 和 SAM3 都不改。** 只多了单帧检测和每个种子一次 tracker 传播。
- **不换词。** rescue 用的就是 Ground 输出的那个词，这和已排除在论文之外的 backup 类别词不是一回事。

## 5. 为什么认为 rescue 对口：训练缓存里的失败结构

训练缓存是用**训练时的类别标签**召回的，所以词基本是对的。也就是说，这些失败主要不是 Ground 给错词，而是 SAM3 那一侧没出来。

| 缓存 | 总数 | J\*<0.5 | 只召回 1 个候选 | 达到 7 个上限 | 失败中 J\*<0.1 |
|---|---|---|---|---|---|
| DAVIS train（recall24/keep7） | 553 | 166 | 82（49%） | 30（18%） | 138 |
| Ref-YTVOS train（recall24/keep7） | 12,858 | 1,708 | 710（42%） | 454（27%） | 1,064 |

数据来自 `crf_sam3_attn/cache_reports/*_max_j_lt_0p5.json`。这是 overlay 补跑之前的数字，你表里的 26.94% / 10.78% 是补跑之后的。

- **最大的一类是"只召回 1 个，但 GT 是另一个"。** 比如 tuk-tuk 里 "a girl on the left / on the right" 都只出了 1 个 girl（lindy-hop、classic-car 则属于下面"达到上限"那类拥挤场景）。这正是"同类、可见、但分数没到 0.7"的典型情形。
- 你 6 月的补跑分析（`davis17_failure_rerun_score_sum_keep7_latest_analysis_20260622.json`）里，把 girl 换成 person 救回了 43 条（如 tuk-tuk 的 J 从 0 涨到 0.976）。这说明这些目标 SAM3 是能分割的，只是在原词下分数不够。rescue 不换词，而是在热力图圈出的区域里降低门槛，针对的是同一个问题。
- **"达到上限"那一类**（拥挤场景）热力图也能起作用：块里有响应、却没有被保留的那 7 个覆盖到，同样会触发。
- **J\* 在 0.1–0.5 之间的那一类**（部分覆盖、碎片）不是本方案的主要目标。如果占比高，后续要做 tube 合并。

## 6. 实验顺序与判定

1. 在服务器上跑 `check_sam3_api`，确认低阈值检测和 tracker 种子两条路都能走通（约 1 分钟）。
2. 对 DAVIS train 的 166 条失败样本导出热力图，跑 `heatmap_diag`。看两个数：`frac_frames_gt_found`（门控能否看到目标区域）和 `uncovered`（目标区域是否确实没被候选覆盖）。
   - 如果 `uncovered` 很低，说明目标块其实已经被某个错误候选覆盖了（例如一个大 mask 把两个人都包进去）。这时应该把覆盖率改成按实例计算，或者降低 `--coverage-thr`。
3. 跑 `run_p1a --modes rescue,point,oracle_gt`。
   - `oracle_gt` 是"给一个完美种子"的上限，告诉你单种子路线最多能救回多少。
   - `rescue` 和 `point` 是可部署的版本。
4. 在 200 条成功样本上测误触发（平均新增候选数）。
5. 用 `analyze` 换算成全集 Recall@0.5（`--total-n 553 --total-recall 73.06`）。之后再上 Ref-YTVOS 失败集，最后用 Ground 预测词在 ReVOS 验证集上跑（`--recompute-text --category-json`）。

**值得接入 Verify 的标准（建议）：** rescue 在失败集上救回的比例达到 `oracle_gt` 的一半以上，并且成功样本上平均新增候选少于 0.5 个。

## 7. 和论文叙事的关系

- Method 里写"Ground 的 response map R 是显式中间表示"，这个方案就是让 R 在推理时被真正用起来：Ground 同时给出 *what*（ĉ）和 *where*（R）。Recall 阶段变成"文本召回 + 证据驱动的补全"，并且全程免训练。
- 不改变"Ground 对所有数据集都是 target-query grounder"的设定，也不引入备用词。
- 做成消融很自然：text only → + rescue → + point，加上 oracle 种子上限，再加上误触发代价。

## 8. 风险与后续

- **slot 塌缩**是 Ground 训练目标造成的：只监督最匹配的那个 slot，其他 slot 没有任何约束。如果以后想让 Ground 直接给出实例级假设，需要改训练，比如加 no-object 类的匈牙利匹配，或者把同类其他实例当作额外的匹配目标。这属于需要训练的方向，不在本包范围内。
- **热力图 token 分辨率粗**，小目标可能连块都形不成。可以把 `--frames-per-sample` 提到 5 或 8，或者提高 Ground 输入分辨率，但要先确认 Ground 在更高分辨率下的响应不会变差。
- **需要"哪一个实例"的情形**（例如 the leading car），热力图本身给不出答案。如果 rescue 补回来的候选很多，可以再接上调研报告里的 P1-B：用 Qwen3-VL 在关键帧上输出目标框，作为实例级种子。
- **`track_seed` 是在不带文本的会话里加 tracker 点提示。** 源码路径看起来支持，但没有在真实权重上跑过，所以第 1 步自检必须先做。
